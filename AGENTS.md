# Правила роботи з проєктом (AGENTS.md)

Цей файл фіксує правила та конвенції, за якими створено `index.html` — інтерактивну «Карту статистичного аналізу даних + A/B тестування». Дотримуйся їх під час будь-яких змін, щоб зберегти стиль, структуру та методологічну цілісність документа.

## 1. Структура документа

- Один автономний HTML-файл (`index.html`): стиль, структура, JS — усе в одному файлі. Без зовнішніх залежностей.
- `lang="uk"` — увесь контент українською.
- Ієрархія: `header.top` → секції `section.scheme` → `footer`.
- Кожна секція має унікальний `id` (`s0`…`s8`) і номер `span.scheme-num` (00–08).
- Навігація — `nav.toc` із якірними посиланнями на секції.

## 2. Візуальний стиль (палітра)

CSS-змінні у `:root` — єдине джерело істини для кольорів:

| Змінна | Роль |
|--------|------|
| `--bg`, `--ink`, `--ink-soft`, `--line`, `--card` | базова тема |
| `--accent-blue`, `--accent-coral`, `--accent-teal`, `--accent-purple`, `--accent-amber`, `--accent-green`, `--accent-red` | кольори секцій / акцентів |
| `${accent-*}-bg` | світлий фон для блоків |

- Шрифти: заголовки — `Georgia`/serif; тіло — системні sans-serif; код/меню — `--mono` (JetBrains Mono / Consolas).
- Для кольорових блоків використовуй класи `c-blue`, `c-teal`, `c-green`, `c-amber`, `c-coral`, `c-purple` (або `var(--accent-*)` інлайн).

## 3. Типові компоненти

- **Схеми (flowcharts)** — SVG у `.diagram-card`. Кожен клікабельний елемент — `<g class="node" data-detail="...">`.
- **Панелі деталей** — `.detail-panel#panel-<id>` з `.detail-inner`; розкриваються кліком (JS нижче). `data-color` задає колір рамки.
- **Словник термінів / кнопки** — `.term-grid > .term-node[data-detail]`.
- **Метрики з формулою** — кнопці `.term-node` автоматично додається клас `.has-formula` (товстіша зовнішня amber-рамка), якщо її панель містить `<code>` із символом `/` (JS наприкінці файлу перевіряє `textContent.indexOf('/')`). Щоб метрика з формулою виглядала як формульна, у панель потрібно включити хоча б один `<code>` із «/» (напр. похідну формулу `CR (%) = Conversions / Visits × 100%`); для лічильників без ділення (напр. `Conversions`) це єдиний спосіб підсвітити рамочку.
- **Навігація між секціями** — `.pipeline-next` (стрілка «➡ Результат передаємо далі») і `.pipeline-context` (блок «Що отримуємо / Проблема / Рішення»).
- **Таблиці даних** — `.dc-table`.

## 4. Інтерактивність

- Клік по `.node`, `.term-node`, `.clickable-heading` розкриває відповідну `.detail-panel`.
- Поведінка реалізована в єдиному `<script>`: в один момент відкрита лише одна панель у межах секції.
- Кожному клікабельному елементу обов'язково має відповідати панель з `id="panel-<data-detail>"`; інакше клік не спрацює.

## 5. Пайплайн і логіка

- Вісім послідовних етапів (00–08): Класифікація → Викиди → Вибірка та надійність → Кореляція → Порівняння (A/B) → Розмір вибірки → Моніторинг → Аналіз результатів.
- Кожен етап закінчується блоком «➡ Результат передаємо далі» з посиланням на наступну секцію.
- Методологія точна: парний t-тест перевіряє нормальність різниць; Велча — коли дисперсії нерівні; непараметричні тести для ненормальних; p-value порівнюється з α = 0.05.

## 6. Код та літерація

- Код-примеры у `<code>` усередині `.detail-inner` (scipy.stats, statsmodels, pingouin).
- Завжди вказуй конкретну функцію (напр. `scipy.stats.ttest_ind`, `statsmodels.stats.api.NormalIndPower().solve_power(...)`).
- Жодних зовнішніх тестових фреймворків: це статичний HTML без build-етапу.

## 7. Загальні правила написання

- Не додавай зовнішні CSS/JS фреймворки без потреби.
- Зберігай одностиль: кольори лише через існуючі `var(--...)`.
- Дотримуйся української спельки та термінології аналізу даних.
